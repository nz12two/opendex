<Callout type="note">
O OpenCode **não** possui um sistema de "workflows" em YAML (como `.opencode/workflows/` ou uma action `opencode/action@v1`). Em vez disso, ele orquestra trabalho através de **agentes** (primary + subagents), **sessions** e o fluxo **build/plan**. Este guia explica como combinar esses recursos para montar fluxos de trabalho.
</Callout>

## Como o OpenCode orquestra trabalho

O OpenCode organiza o desenvolvimento em torno de **sessions** (conversas persistentes) e **agentes**. Um fluxo típico combina:

- **Primary agents** (`build` e `plan`) — o assistente principal que você alterna com **Tab**.
- **Subagents** (`general`, `explore`, `scout`) — especializados, invocados via **@ mention** ou pela Task tool.
- **Sessions** — cada sessão guarda o contexto e o histórico de uma tarefa.

## O fluxo build/plan

O fluxo mais comum é alternar entre os dois primary agents:

1. **Plan mode** (tecla **Tab**): o agente `plan` analisa o problema e **sugere** mudanças sem aplicá-las. Ideal para planejar antes de agir.
2. **Build mode** (tecla **Tab** de novo): o agente `build` aplica as mudanças de fato, com todas as tools habilitadas.

Esse ciclo "planeja → implementa" é a base de qualquer fluxo de desenvolvimento no OpenCode.

## Combinando agentes para fluxos

Você pode montar fluxos mais complexos combinando agentes:

- **Planejar:** use o agente `plan` para analisar o problema e propor uma abordagem.
- **Implementar:** mude para o agente `build` para aplicar as mudanças.
- **Tarefas paralelas:** use o subagente `general` para rodar unidades de trabalho em paralelo.
- **Explorar o código:** use o subagente `explore` (read-only) para entender uma codebase sem modificar nada.
- **Pesquisar dependências:** use o subagente `scout` para consultar docs externas e dependências.

## Usando sessions

Cada sessão mantém o contexto de uma tarefa. Você pode:

- Criar uma nova sessão com `<leader>n` (leader key default é `ctrl+x`).
- Listar sessões com `<leader>l`.
- Renomear com `ctrl+r`, deletar com `ctrl+d`, compactar com `<leader>c`.
- Interromper com `escape`.

Via CLI:

```bash
opencode session list
opencode session delete <id>
```

## Automação de CI/CD

Para automação (CI/CD, scripts, tarefas não-interativas), o OpenCode oferece o modo **run** via CLI, em vez de um sistema de workflows YAML:

```bash
opencode run "Refactor this module"
opencode run --auto "Run tests and fix failures"
```

O `opencode run` executa o OpenCode em modo não-interativo, o que permite integrá-lo a pipelines de CI/CD e scripts.

<Callout type="tip">
Combine `opencode run` com o modo `--auto` (auto-aprovação) para automação headless. Lembre-se de que permissões `deny` explícitas ainda são respeitadas.
</Callout>

## Boas práticas

<Callout type="tip">
**Planeje antes de agir:** use o `plan` para validar a abordagem antes de deixar o `build` aplicar mudanças.
</Callout>

<Callout type="tip">
**Use subagents para paralelismo:** o `general` roda unidades de trabalho em paralelo, acelerando tarefas independentes.
</Callout>

<Callout type="tip">
**Mantenha sessions organizadas:** use uma sessão por tarefa e compacte (`<leader>c`) quando o contexto ficar longo.
</Callout>
